模块导读与教学设计

05 — 特征工程、SHAP 与 3D 分子（Feature Engineering & Molecular Informatics）

前四讲里，我们一直在往模型里“加东西”：加描述符、加指纹、加交叉验证、加不确定性。本讲反过来做两件事——减法与解释。

一方面，真实课题里随手就能算出几百上千个描述符，但其中绝大多数彼此高度共线（MolWt、HeavyAtomCount、MolMR、LabuteASA 本质上都在说“分子有多大”），冗余特征会稀释重要性、拖慢训练、在小样本上制造过拟合。我们要学会把 29 维压到 10 维而精度不掉。

另一方面，导师和审稿人真正追问的从来不是 \(R^2\) 的第三位小数，而是“对我合成的这一个分子，模型凭什么这么判”。本讲用合作博弈论的 Shapley 值，把单个分子的预测值严格拆解成各描述符的推拉贡献。

最后，本讲还要兑现一个从第一讲就埋下的伏笔：Yalkowsky 通用溶解度方程里的熔点项 \(-0.01(T_m - 25)\)。熔点来自三维晶体堆积，任何 2D 描述符都算不出来——我们用 RDKit 把分子“站起来”变成三维构象系综，再用 PubChem API 把真实的实验熔点抓回来，亲手补上这块缺失的拼图。

与前四讲的前后呼应

前序模块埋下的伏笔 本讲在何处兑现与深化
02c：置换重要性显示打乱 MolWt 时模型纹丝不动，因为 HeavyAtomCount 在旁边“打掩护” 05a 第 4 & 11 节：相关矩阵给出 \(\lvert r(\text{MolWt}, \text{HeavyAtomCount})\rvert \approx 0.94\) 的直接证据；并排对比 MDI、置换重要性与 SHAP 三种度量在共线特征下的不同表现——置换重要性把 HeavyAtomCount 压到接近 0，而 SHAP 仍按模型实际使用情况给它分摊贡献
02c：MDI 与置换重要性都只给出一个全局数字，无法解释“为什么模型判这一个分子难溶” 05a 第 8–10 节：从 Shapley 四公理出发，用瀑布图把单个分子的预测值拆成 \(\mathbb{E}[\hat{y}] + \sum_i \phi_i\)，给出可直接写进论文讨论部分的归因句
02c：Yalkowsky 方程的熔点项 \(T_m\) 不在 10 个 2D 描述符里，导致“砖头粉”型高对称分子被系统性漏报 05b 第 6–7 节：用 PubChem PUG-View 抓回 79 个分子的实验熔点，加入后 GSE 的 RMSE 从 1.54 降到 1.06（改善约 31%）；最小二乘拟合出的系数与 Yalkowsky 的 \(-1\)、\(-0.01\) 在方向与量级上一致
02b / 03a：高维特征需要降维，但 PCA 会让主成分失去化学意义 05a 第 3–6 节：特征选择（保留原始描述符，可解释）与特征提取（PCA，不可解释）的分工；29 → 10 维后每一列仍能向实验同行逐条讲清楚
03b / 04a：Tanimoto 相似度与分子指纹都建立在 2D 拓扑之上 05b 第 1–3 节：ETKDG + MMFF 生成三维构象系综，PMI 形状三角把“棒状 / 盘状 / 球状”量化；并苯类聚在盘状顶点（PBF 接近 0），这正是其 herringbone 堆积与高迁移率的几何根源
07a（后续）：梯度下降拟合 \(\log S\)–\(\log P\) 得到的斜率约 \(-0.41\)，远比 Yalkowsky 的 \(-1\) 平缓 05b 第 7.1 节：原因是全量数据上高熔点分子的晶格效应被吸收进了残差；一旦把 \(T_m\) 显式放进模型，\(\log P\) 的系数立刻朝理论值靠拢

数据集说明

  • data/solubility.csv：AqSolDB 水溶解度数据集（9,482 个有机分子，自带 17 个 RDKit 描述符列），用于 05a 全程的特征选择与 SHAP 分析、05b 第 4 节的 3D 描述符收益对照实验，以及 05c 第一部分习题；

  • data/melting_points.csv：本讲新增。79 个常见有机分子（并苯、杂环、酚类、羧酸、农药、甾体激素等）的实验熔点数据集，共 7 列：

    列名 含义
    name 查询用的通用名
    cid PubChem 化合物编号
    aqsoldb_name 该分子在 AqSolDB 中的名称（常与 name 不同，因此不能按名字对齐）
    SMILES RDKit 规范化 SMILES（跨库对齐的依据）
    Tm_C 实验熔点 / °C，由 PubChem PUG-View 的 Melting Point 注释解析并取多来源中位数
    logS AqSolDB 实测水溶解度
    MolLogP RDKit 计算的 \(\log P\)

    该文件正是用 05b 第 6 节的 fetch_melting_point() 代码批量抓取、再按规范化 SMILES 与 AqSolDB 对齐生成的，随课程打包以保证在没有网络的课堂上也能完整复现第 7 节的分析。

依赖说明

除课程 requirements.txt 中的基础依赖外，本讲额外需要 shap（用于 05a 第 9–11 节）：

pip install shap

05a 中的导入格已内置 try / except ImportError 自动安装回退，在 Colab 上无需手动处理。

05b 第 5–6 节会访问 PubChem 的公开 API（无需注册、无需 API Key）。若课堂网络不通，相关代码格会打印提示并跳过，后续分析自动改用本地的 data/melting_points.csv，不影响整节课的完整性。
